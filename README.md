# Отметка — журнал посещений

Исходники можно хранить в GitHub. Сайт использует сервер для проверки паролей и базу для журнала входов. Эта версия подготовлена для Cloudflare Workers с базой D1. После публикации посетители входят под логином «Отметки». Аккаунты GitHub и Cloudflare нужны владельцу для публикации.

## 1. Загрузите проект на GitHub

1. Распакуйте архив. На верхнем уровне должны быть видны `package.json`, `wrangler.jsonc`, `README.md` и папки `core`, `public`, `local`, `migrations`, `src`.
2. Откройте [создание репозитория](https://github.com/new). Для описанного ниже способа выберите видимость **Public** и название, например `otmetka`. Этот выбор делает исходный код доступным для просмотра.
3. В пустом репозитории нажмите **uploading an existing file**. Если в нём уже есть файлы, выберите **Add file → Upload files**. Перетащите содержимое распакованной папки и нажмите **Commit changes**.
4. Откройте главную страницу репозитория. В списке файлов сразу должен быть виден `wrangler.jsonc`. Скопируйте адрес репозитория из браузера.

Для хранения исходников или сдачи работы преподавателю этих шагов достаточно. Для одной только сдачи исходников можно выбрать и приватный репозиторий, если у получателя есть доступ.

## 2. Откройте сайт по интернет-ссылке

Вставьте адрес вашего публичного репозитория после `?url=` в следующем шаблоне, затем откройте получившийся адрес в браузере.

```text
https://deploy.workers.cloudflare.com/?url=https://github.com/ВАШ-ЛОГИН/otmetka
```

1. Войдите в Cloudflare и подключите GitHub. Мастер предложит скопировать исходники в репозиторий для публикации. Если имя исходного репозитория уже занято, для новой копии можно выбрать, например, `otmetka-live`.
2. В конфигурации подтвердите создание базы D1 для привязки `DB`. При этом мастер подставит идентификатор созданной базы вместо значения шаблона. Команда публикации — `npm run deploy`. Она применяет SQL-миграции из папки `migrations` и публикует сайт.
3. Нажмите **Deploy**. Дождитесь успешного завершения и откройте выданный адрес на `workers.dev`. Для последующих обновлений редактируйте репозиторий, подключённый к опубликованному Worker.

Это новая установка с пустым журналом. Данные вашего локального файла SQLite и предыдущего сайта остаются в своих базах.

## 3. Назначьте себе права администратора

На публичном сайте каждый зарегистрированный аккаунт получает обычные права. Сначала зарегистрируйтесь, войдите и запишите свой **ID аккаунта** из кабинета и точный логин.

В панели Cloudflare откройте базу D1, подключённую к этому Worker, и её SQL-консоль. В запросе ниже замените пример `17` и `anna` на свой ID и свой логин в нижнем регистре, затем выполните запрос.

```sql
UPDATE accounts SET role = 'admin' WHERE id = 17 AND login = 'anna';
```

Обновите страницу кабинета. Теперь администратору доступна сводка по всем пользователям. Проверьте на втором аккаунте, что обычный пользователь видит только свою историю.

## Просмотр журнала и локальная версия

В кабинете установите период и нажмите «Показать». Кнопка «История» выводит даты и время каждого входа. Кнопка «Консоль» открывает команды `сводка`, `история ID` и `помощь`.

Для локального запуска нужен Node.js 22.13 или новее. Из корня проекта выполните `node local/server.mjs`. Адрес — `http://127.0.0.1:8000`. В отдельном терминале команда `node local/console.mjs` откроет консольный клиент. Подробности — в [local/README.md](local/README.md).

Чтобы подключить консольный клиент к опубликованной базе, задайте `OTMETKA_URL` равным HTTPS-адресу вашего сайта перед запуском клиента. В PowerShell используйте `$env:OTMETKA_URL = "https://ИМЯ-ПРОЕКТА.ПОДДОМЕН.workers.dev"`, в Bash — `export OTMETKA_URL="https://ИМЯ-ПРОЕКТА.ПОДДОМЕН.workers.dev"`. Затем запустите `node local/console.mjs`.
